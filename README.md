# Balyk.kz Marketplace Prototype

Интернет-магазин морепродуктов на Node.js, PostgreSQL и статическом клиенте.

## Запуск

```bash
npm run dev
```

Откройте `http://localhost:3000`.

## Что внутри

- `server.js` - простой Node.js сервер для локального запуска.
- `public/` - витрина магазина: каталог, поиск, карточка товара, корзина, оформление заказа, профиль.
- Избранные товары можно сохранять и отбирать в каталоге; список хранится в браузере.
- `database/schema.sql` - структура PostgreSQL.
- `database/seed.sql` - стартовые категории и товары для pgAdmin.
- В каталоге 31 товар; фотографии хранятся локально в `public/images/`, цены и фасовка синхронизируются из `database/seed.sql`.
- `public/` - мобильная навигация, витрина, корзина и панель администратора.
- Сессии пользователей хранятся в PostgreSQL; пароли сохраняются в виде scrypt-хеша.
- Восстановление пароля отправляет одноразовый шестизначный код по SMTP. Для включения заполните `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_FROM`, при необходимости `SMTP_USER`/`SMTP_PASSWORD` и случайный `PASSWORD_RESET_SECRET` длиной не менее 32 символов в `.env` (образец — `.env.example`). Код действителен 10 минут, после пяти неверных попыток аннулируется. Без SMTP-настроек API явно сообщает, что восстановление ещё не включено.
- Данные профиля можно изменить в личном кабинете; сохранение требует подтверждения текущим паролем.

## Первый запуск

1. Установите Node.js 22+ и PostgreSQL.
2. Создайте базу данных и скопируйте `.env.example` в `.env`.
3. Заполните подключение к PostgreSQL. Для локального администратора укажите `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`; используйте отдельный случайный пароль. Не записывайте рабочие учётные данные в README, Git или другие отслеживаемые файлы.
4. Запустите `npm ci`, затем `npm start`.
5. Откройте `/api/health` и убедитесь, что база подключена. Схема, каталог, таблица ролей и хранилище сессий применяются при старте.

При каждом старте заданные `ADMIN_EMAIL` и `ADMIN_PASSWORD` создают администратора или обновляют пароль этой учётной записи. В production приложение требует эти параметры для зелёной проверки готовности. На хостинге храните их в секретах окружения, а не в репозитории. Для смены пароля задайте новое значение `ADMIN_PASSWORD` в `.env` (или в хостинг-секрете) и перезапустите сервер.

Заказы и список покупателей доступны после входа администратором через ссылку «Админка». Запросы к административным API проверяют роль на сервере. Статусы заказов: новый, подтверждён, выполнен, отменён.

## Проверки перед публикацией

```bash
npm run check
npm test
```

Перед загрузкой в Git убедитесь, что `.env` не добавлен в коммит. Сам Git не предоставляет сервер для Node.js и базы данных.

## Развёртывание на сервере через Docker Compose

Для production-публикации в репозитории есть `Dockerfile`, `docker-compose.yml` и конфигурация Caddy. Compose запускает приложение, PostgreSQL и HTTPS reverse proxy; база данных не публикуется наружу, а приложение подключается к ней отдельной ролью без прав суперпользователя. Данные PostgreSQL и сертификаты Caddy хранятся в именованных Docker volumes.

1. На Linux-сервере установите Docker Engine с Compose plugin, настройте DNS `A`-запись домена на публичный IP сервера и разрешите входящие TCP-порты 80 и 443 (а также UDP 443 для HTTP/3).
2. Клонируйте репозиторий на сервер, скопируйте `.env.example` в `.env` и заполните `SITE_ADDRESS` своим доменом, `ADMIN_EMAIL`, `ADMIN_PASSWORD` и PostgreSQL-пароли. Используйте отдельные длинные случайные значения для `PGPASSWORD` и `POSTGRES_PASSWORD`; пароль администратора должен быть не короче 12 символов и содержать заглавную букву, строчную букву и цифру. Подходящий формат пароля администратора: `Balyk-` плюс результат `openssl rand -hex 32`. Ограничьте доступ к `.env` (`chmod 600 .env`) и не добавляйте его в Git.
3. Запустите приложение: `docker compose up -d --build`.
4. Проверьте `docker compose ps`, журналы `docker compose logs --tail=100 app db caddy` и endpoint `https://ваш-домен/api/health`. Готовность означает HTTP 200 и `database: "connected"`.
5. При публикации обновлений используйте `git pull` и `docker compose up -d --build`. Обычная команда `docker compose down` сохраняет данные; **не используйте `docker compose down --volumes`** для штатной остановки — она удалит базу и сертификаты. Регулярно сохраняйте резервные копии базы данных отдельно от сервера.

В production сервер не запускается, если не заданы администраторские секреты или недоступна PostgreSQL. Не выставляйте приложение или БД напрямую в Интернет: публичный трафик принимает Caddy, который автоматически настраивает HTTPS и передаёт запросы приложению по внутренней сети Compose.

## PostgreSQL / pgAdmin

1. В pgAdmin выберите существующую базу `balykkz`.
2. Выполните `database/schema.sql`, затем `database/seed.sql`.
3. Создайте файл `.env` в корне проекта и укажите пользователя PostgreSQL:

```env
PGHOST=localhost
PGPORT=5432
PGDATABASE=balykkz
PGUSER=ваш_пользователь_pgadmin
PGPASSWORD=ваш_пароль
```

Либо задайте одну переменную `DATABASE_URL`. Пароль не нужно добавлять в git.

После этого запустите `npm run dev` и откройте `http://localhost:3000`.

Сервер автоматически применяет схему при запуске, читает каталог из PostgreSQL и сохраняет заказы. Авторизованные покупатели видят историю своих заказов в профиле; новые заказы привязаны к аккаунту, а прежние несвязанные заказы продолжают находиться по номеру телефона. В заказе указываются город, район, улица, дом, квартира или офис, подъезд/этаж и комментарий курьеру.
